and ACTIVE local user, matching session/user identity, and an explicit active
GLOBAL **OWNER or ADMIN** assignment. Legacy `users.role=ADMIN`, token claims,
CONTENT_MANAGER/STUDENT and COURSE assignments do not authorize them.

no launcher allowlist changed. The existing global 503 barrier stays ahead of this
router. No special path bypasses it.

Mutations reuse the existing lazy, pinned dedicated `ccna_rbac_manager` transport

still trusted to supply the verified actor UUID; SQL does not verify Clerk itself.
Activation must explicitly accept/review that existing management trust boundary.

SQL grants app EXECUTE on bounded draft reads and manager EXECUTE on draft changes

Existing role permissions, lesson RLS, content access, learning data and CCNA

## API contracts for future UI work

Base: `/api/admin/catalog`. All responses are JSON and `private, no-store`.
No UI is wired to these new operations yet; the existing 9F disabled controls
remain disabled. Authentication is always required.

| Method/path | Contract |
| --- | --- |
| GET `/tracks?page=1` | Draft tracks only; no parent parameter |
| GET `/courses?parentId=<track UUID>&page=1` | Draft courses under the exact existing track |
| GET `/versions?parentId=<course UUID>&page=1` | Draft versions under the exact existing course |
| POST `/tracks` | Create DRAFT track with immutable slug |
| POST `/courses` | Create DRAFT course under `trackId` |
| POST `/versions` | Create DRAFT version under `courseId`, with dedicated existing `blueprintId`, `versionKey`, `catalogKey` |
| PATCH `/tracks/:id`, `/courses/:id`, `/versions/:id` | Edit permitted display metadata of the exact unused DRAFT only |

GET query objects are strict: page defaults to 1, range 1–10000, fixed 20 items;
unknown parameters are rejected. Missing parents are 404 rather than fabricated
empty inventories. Lists include `{items,total,page,pageSize:20}`. Each item and
successful mutation return:

```json
{
  "id": "<actual resource UUID>",
  "status": "DRAFT",
  "version": "2026-11-10T01:00:00.123457Z",
  "title": "Draft title",
  "description": "",
  "displayOrder": 0
}
```

`version` is an **opaque, exact UTC microsecond timestamp token** from `updated_at`,
not a JS Date or an integer. Preserve all six fractional digits; do not round it.
List DTOs expose editable fields only; immutable identity/parent fields are not
implicitly editable. This contract is documented here, with no guessed generated
client or OpenAPI publication. Future UI/codegen integration is separate work.

POST requires these common fields (all required):

```json
{
  "requestId": "<client-generated UUID, retained for this exact operation>",
  "title": "Draft title",
  "description": "",
  "displayOrder": 0,
  "reason": "Reviewed catalog draft"
}
```

Add `slug` for tracks; `slug,trackId` for courses; or
`courseId,blueprintId,versionKey,catalogKey` for versions. UUID parents are verified
relationally, never created from arbitrary IDs. Creation IDs are generated by SQL.
PATCH includes only common fields plus `expectedVersion` from the previous receipt;
`slug`, parents, binding keys, status, caller actor, scope and IDs in JSON are rejected.
`X-Admin-Session` must match the verified session for POST **and PATCH**. JSON body
limit is 16 KiB. No PUT, publish, retirement, deletion or bulk endpoint exists.

Validation: trimmed title 1–180 characters; description up to 4000; displayOrder
integer 0–100000; trimmed reason 5–500; slug/catalogKey lowercase hyphen-separated
ASCII up to 100; versionKey lowercase alphanumeric with dots/underscores/hyphens
up to 100. Required fields, types and extra-key rejection are checked by API and
SQL. SQL casts additionally reject invalid UUID/date values. Parameterized values
and fixed explicit kind branches are used; no user-controlled SQL identifiers.

Parent tracks/courses must be DRAFT or ACTIVE, never RETIRED. A version additionally
requires an existing **DRAFT** blueprint, with the existing unique blueprint binding.
The ACTIVE CCNA blueprint cannot be borrowed. No blueprint creation, fake source
URL, certification verification, canonical CHECK replacement or taxonomy editor
is added. Preparing a suitable reviewed draft blueprint is a separate prerequisite.

## Optimistic concurrency, idempotency and preservation

Proposed source: `lib/db/drizzle/proposed/0023_catalog_draft_management.sql`;
**unregistered/unapplied** after separately reviewed 0018–0022 prerequisites.
It adds one immutable receipt table and narrow functions/triggers. No rows are
seeded, no existing data backfilled, and no historical SQL/journal/snapshot changed.

- SQL updates the existing GLOBAL authority guard before reauthorization, following
  0018's serialization rule. It locks the ACTIVE actor and checks OWNER/ADMIN.
  This prevents a concurrent authority revocation from being ignored under a stale
  repeatable-read snapshot. The guard revision can advance on a successful logical
  retry; catalog state and the original receipt/event are not duplicated.
- An actor/request unique key plus canonical request digest binds operation kind,
  target, exact expected token and payload. An identical authorized replay returns
  its original receipt; changed parameters conflict. The receipt describes that
  operation, not necessarily the resource's current state after later changes.
- Edits lock the target, require DRAFT and the exact token, and advance `updated_at`
  by at least one microsecond. Metadata mismatch, wrong ID/status, or a nonadvancing
  response token is unverified, never reported as success by the API.
- Parents/blueprint are rechecked and share-locked. Edit dependency inspection takes
  SHARE table locks on chapter bindings, enrollments and epochs so incoming writes
  cannot race it. A used/bound version and its ancestor track/course cannot be
  edited through this API. Thus existing CCNA catalog bindings and their display
  metadata are protected even when the metadata itself was initially backfilled
  as DRAFT. IDs, slugs, bindings and keys are never updated.
- The receipt/event is inserted in the **same SQL transaction** as the catalog
  mutation. Its failure aborts the mutation. Events reject UPDATE/DELETE/TRUNCATE.
  New forward version-update protection rejects changes to ACTIVE/RETIRED versions
  without altering the older identity guard. Future lifecycle work must review
  this guard explicitly; there is no retirement bypass in this package.
- No automatic retry. Serialization/deadlock/lock timeout, stale tokens, duplicates,
  protected data and FK conflicts return sanitized 409; authority denial 403;
  missing target/parent 404; malformed values 400; inactive/unverified backend 503.
  A lost/uncertain commit must be diagnosed before a new request. An exact request
  may only be replayed deliberately with the same ID and payload after review.

Real PostgreSQL concurrent behavior is **not proven by offline fixtures**. Before
activation rehearse simultaneous stale edits, duplicate creates/replays, role and
status revocations, parent retirement, incoming bindings/enrollment races, audit
insertion failure and transaction rollback under READ COMMITTED/REPEATABLE READ.
Locks may produce deadlocks with external writers; PostgreSQL must abort one
transaction and the caller must not retry automatically. The locks also have a
performance impact that needs isolated load acceptance.
