## Import sequence through the existing application

Perform database-affecting steps only after approval, using real Clerk ADMIN access. Do not store tokens, use fake auth, connect directly to PostgreSQL or bypass preview.

1. Open /admin/taxonomy. Compare any existing 200-301 / 1.1 record with this plan. If absent, use **Create blueprint** with blueprint.create.json's fields, starting DRAFT. Reuse only after confirming version, source and bindings. Stop on conflicts; do not invent an “official” version or alter an existing record to match.
2. Create the six domains from their template and real blueprint selection. Create the 53 objectives in their corresponding domains. Existing natural-key matches require explicit comparison before reuse; never duplicate or silently replace them.
3. Open /admin/topics. Enter each topics.create.json object's name, slug, description, order and DISABLED status in **Create a topic**. Record its real ID against the exact slug. A same-slug record must match the reviewed pack before reuse; otherwise stop.
4. Copy bindings.example.json to a new bindings.json in this folder. Fill the blueprint ID, six domain IDs and 24 topic IDs from the actual Admin catalog. Keep packId unchanged; this pack assigns no fake database IDs.
5. Run the offline command below. It validates exact keys/UUID structure and reviewed hashes, writes a fresh timestamped subfolder and refuses overwriting output. **Zero database actions.**
6. Open /admin/import and select the generated **questions.import.csv**, not questions.source.csv. Press **Validate and preview**. A clean context should return 60 accepted, zero rejected/duplicates. Existing equivalent content reduces accepted count; inspect every row and stop on unexpected conflicts.
7. Review answers, explanations and objective mappings. Checking the acknowledgement/opening confirmation writes nothing. Only **Confirm draft import** creates accepted rows. The existing importer uses a transactional batch and captures revisions. Preserve its actual returned question IDs in an import receipt; do not infer IDs from sequences.
8. If publication was approved, edit **only those new questions** to ACTIVE in /admin/questions and **only those new topics** to ACTIVE in /admin/topics. Preserve their content/options/mappings. No bulk publish endpoint exists; do not substitute SQL.
9. Verify the real learner dashboard, /topics and /practice. Explanations/correct answers appear through the existing submission-feedback flow, not a new public answer-key endpoint.
